These fixes are on the beta branch only. Production is unchanged until you merge. Ticks are saved in this browser.

The database itself is fast. The time went into travel:

  • The app's server ran in Mumbai (Vercel region bom1), but the database is in Tokyo (Supabase ap-northeast-1). Every database call was a Mumbai → Tokyo → Mumbai trip.
  • One page makes about 6 of those trips one after another. The security check that runs before every request makes 3 (check the login, read the account, check the blocked list), then the layout and the page make the rest. Every API call (notifications, messages, …) repeats the 3 security trips.
  • Separately, every card blurred whatever was behind it (backdrop-filter), and big blurred shapes pulsed non-stop. The browser redraws those on every scroll, which is the "laggy" feeling.

Tests: 166/166 and 3/3 security tests pass, typecheck clean, production build succeeds.

Left out on purpose

  • Merging the account read and the blocked-list check into one call. It needs a new database migration. With the server next to the database that trip costs a few ms, so it isn't worth it now.
  • Loading notifications on the server. They load after the page is already on screen, so they don't slow the page itself.
  • Moving the database to Mumbai. The other way to remove the distance, but it means a new Supabase project, a data copy and some downtime. Only worth it if beta still feels slow from India after this change.
